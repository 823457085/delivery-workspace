# 前端技术方案常见问题库

本文件用于沉淀前端技术方案生成和审核过程中常见的问题。后续可持续补充到 AI 审核规则和优秀样例库中，让方案生成质量越来越稳定。

---

## 一、AI 瞎编类问题

### 1. 编造不存在的接口

问题表现：

- AI 写出接口路径，但接口文档中不存在；
- AI 按命名习惯推测接口；
- AI 把“可能需要接口”写成“依赖某接口”。

示例：

```markdown
依赖接口：POST /api/export/orderList
```

但输入材料中没有任何接口文档或后端确认。

处理方式：

- 接口必须来自接口文档、Mock 或后端确认；
- 没有接口时写“待确认：当前输入材料未提供导出接口”；
- AI 审核时将无依据接口标记为 P0 或 P1。

---

### 2. 编造不存在的字段

问题表现：

- AI 写出接口字段，但接口文档中不存在；
- 字段名看起来合理，但没有来源；
- 字段类型和 Mock 数据不一致。

示例：

```markdown
返回字段：exportStatusName
```

但接口只返回 `exportStatus`。

处理方式：

- 字段必须来自接口文档或 Mock；
- 字段映射必须标注来源；
- 未确认字段写入待确认清单。

---

### 3. 编造不存在的组件

问题表现：

- AI 写“复用 AdvancedSearchForm 组件”，但代码库没有；
- AI 按常见命名生成组件名；
- AI 没有检索代码就判断组件可复用。

处理方式：

- 复用组件必须来自代码上下文；
- 没有找到组件时写“未发现可直接复用组件，建议新增或待确认”；
- 公共组件改动必须说明影响范围。

---

### 4. 编造权限规则

问题表现：

- AI 默认管理员可操作，普通用户不可操作；
- AI 自行推测角色权限；
- PRD 未说明权限，方案写成确定结论。

处理方式：

- 权限规则必须来自 PRD、权限文档或人工确认；
- 未确认时写“待确认：不同角色是否可见 / 可操作”；
- 权限影响核心流程时通常判为 P0。

---

### 5. 编造埋点规则

问题表现：

- AI 默认添加点击、曝光、提交埋点；
- AI 默认不需要埋点；
- 埋点参数无来源。

处理方式：

- 埋点需求必须来自埋点规范、产品或数据确认；
- 未确认时写“待确认：是否需要埋点 / 监控”；
- 核心转化链路建议至少输出确认问题。

---

## 二、输入缺失类问题

### 1. PRD 缺少验收标准

影响：

- 技术方案无法判断完成标准；
- 测试用例难以设计；
- 产品验收容易反复。

处理方式：

- 输入完整性检查阶段输出 P0；
- 需要产品补充验收标准后再生成完整产物包。

---

### 2. 设计稿缺少状态说明

常见缺失：

- loading；
- empty；
- error；
- disabled；
- no permission；
- 超长文本；
- 弹窗关闭规则；
- 重复提交处理。

处理方式：

- 方案中增加交互状态矩阵；
- 缺失项标记为待确认；
- 核心流程状态缺失时判为 P1 或 P0。

---

### 3. 接口文档未确认

影响：

- 字段映射无法确定；
- 异常处理无法确定；
- AI Coding 容易生成错误数据结构。

处理方式：

- 可先生成页面结构和组件拆分；
- 接口与数据章节保留待确认；
- 进入 Coding 前必须确认关键接口。

---

### 4. 缺少代码上下文

影响：

- 无法判断复用组件；
- 无法判断影响范围；
- 方案容易脱离项目结构。

处理方式：

- 至少提供相关页面、组件、接口封装、类型定义路径；
- 无代码上下文时，不允许写确定的复用组件结论。

## 三、方案结构类问题

### 1. 只有结论，没有依据

问题表现：

```markdown
本需求复用现有列表组件实现。
```

正确写法：

```markdown
根据 src/components/DataTable 的现有能力，可复用其分页、排序和列配置能力。
但批量导出按钮区域是否支持扩展，需要进一步确认或局部封装。
```

---

### 2. 只有实现，没有影响范围

问题表现：

- 写了新增功能，但没写影响哪些页面；
- 修改公共组件但没写回归范围；
- 修改接口封装但没写兼容风险。

处理方式：

- 影响范围必须独立成章；
- 公共组件和公共逻辑必须列回归范围；
- AI 审核重点检查。

---

### 3. 风险描述空泛

问题表现：

```markdown
存在一定兼容风险，需要注意。
```

正确写法：

```markdown
风险：本需求需要修改公共导出工具函数，可能影响订单列表、客户列表两个已有导出入口。
应对：保持原函数入参兼容，新增可选参数；回归订单列表和客户列表导出流程。
```

---

### 4. 测试建议不可执行

问题表现：

```markdown
测试主要功能是否正常。
```

正确写法：

```markdown
测试重点：
1. 有数据时点击导出，生成任务成功；
2. 无数据时导出按钮禁用；
3. 无导出权限时按钮不展示；
4. 接口失败时展示错误提示；
5. 导出中重复点击时防止重复提交。
```

## 四、交互遗漏类问题

常见遗漏：

1. 空态；
2. 异常态；
3. 禁用态；
4. 权限态；
5. 超长文本；
6. 弱网和接口超时；
7. 重复点击；
8. 表单校验；
9. 弹窗关闭规则；
10. 浏览器兼容或响应式适配。

处理方式：

- 设计稿未提供时输出待确认；
- 默认不直接写文案；
- 用交互状态矩阵统一检查。

## 五、下游不可用类问题

### 1. 无法支撑 AI Coding

问题表现：

- 没有页面范围；
- 没有组件拆分；
- 没有接口字段；
- 没有状态处理；
- 没有代码上下文。

处理方式：

- 判为不通过或有条件通过；
- 补齐关键输入。

### 2. 无法支撑测试设计

问题表现：

- 没有验收标准；
- 没有边界场景；
- 没有异常场景；
- 没有权限场景；
- 没有回归范围。

处理方式：

- 补充测试建议；
- 将遗漏场景加入待确认清单。

### 3. 无法支撑产品验收

问题表现：

- 产品不知道验收哪些页面；
- 不知道什么状态算完成；
- 不知道数据如何验证；
- 不知道异常如何展示。

处理方式：

- 补充验收建议；
- 明确验收路径和预期结果。

## 六、常见问题分级建议

| 问题 | 建议等级 |
|---|---|
| 核心需求未覆盖 | P0 |
| 关键接口无依据 | P0 |
| 字段无依据且影响页面展示 | P0 |
| 权限规则未确认且影响操作 | P0 |
| 方案无法支撑 Coding | P0 |
| 缺少关键交互状态 | P1 |
| 回归范围不完整 | P1 |
| 埋点要求未确认 | P1 |
| 风险描述空泛 | P1 |
| 表达不够清晰 | P2 |
| 示例不够完整 | P2 |

## 七、沉淀规则

每次试用后建议沉淀：

1. AI 审核发现的有效问题；
2. 人工评审发现但 AI 未发现的问题；
3. AI 误判问题；
4. 高质量方案片段；
5. 常见待确认问题；
6. 返工原因；
7. 可复用审核规则。

沉淀格式：

```markdown
## 问题标题

### 发生场景

### 问题表现

### 影响

### 处理方式

### 是否加入审核规则
是 / 否

### 示例
```
