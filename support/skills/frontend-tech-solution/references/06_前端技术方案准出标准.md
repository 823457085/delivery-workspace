# 前端技术方案产物包准出标准

本文件用于判断前端技术方案产物包是否可以进入 Coding 阶段。  
准出标准不是要求产物完美或很长，而是要求产物包足够支撑编码、测试和验收，且关键风险已经暴露。

---

## 1. 准出目标

前端技术方案产物包准出后，应满足：

1. 研发负责人可以通过 `00_前端技术方案评审摘要.md` 判断范围、风险和准出建议；
2. 前端研发可以基于 `01_前端实现与接口细节.md` 进入实现；
3. 测试可以基于 `02_测试验收与风险清单.md` 设计测试用例；
4. AI Coding 可以基于 `03_AI_Coding上下文与审核报告.md` 获取已确认上下文；
5. 产品可以确认验收重点和待确认问题；
6. 方案中的关键结论有依据可追溯；
7. 不确定内容已经明确标记为待确认，而不是被写成事实。

说明：

- “只能生成部分产物”只表示可以先生成草案，不等于可以进入 Coding；
- P0 待确认项可以在草案中保留，但处理前不得通过或有条件通过准出；
- AI Coding 上下文只能包含已确认内容，不能混入未确认接口、字段、组件、权限、埋点或实现任务。

---

## 2. 准出项总览

| 序号 | 准出项 | 要求 | 是否阻断 |

## 3. 详细准出标准

### 3.1 产物包结构

必须满足：

- 默认包含 `00`、`01`、`02`、`03` 四个文件；
- 如只能生成部分产物，必须说明缺失文件、缺失原因和待补充材料；
- 四个文件中的需求范围、风险结论、待确认项和准出建议一致；
- 主文档提供附件索引。

不准出场景：

- 缺少必要文件且没有解释；
- 主文档堆满接口字段、测试用例或完整 AI 审核报告；
- 附件内容相互矛盾；
- 关键待确认项只出现在某个附件里，主文档没有暴露。

### 3.2 需求覆盖

必须满足：

- 方案覆盖 PRD 中的核心功能点；
- 方案覆盖产品验收标准；
- 未引入 PRD 中没有的新功能；
- 遵守不做范围；
- 存在需求变更时，已明确变更来源。

不准出场景：

- PRD 的核心需求未覆盖；
- 方案自行扩大需求范围；
- 验收标准缺失或无法验证；
- 不做范围被方案突破。

### 3.3 页面范围明确

必须满足：

- 涉及页面明确；
- 新增、修改、删除内容明确；
- 涉及路由明确；
- 涉及组件明确；
- 权限展示和操作差异明确。

不准出场景：

- 不知道要改哪些页面；
- 不知道新增还是修改组件；
- 页面入口或路由不清楚；
- 权限规则影响功能但未确认。

### 3.4 接口依据明确

必须满足：

- 依赖接口来自接口文档、Mock 或后端确认；
- 请求参数清晰；
- 返回字段清晰；
- 字段映射清晰；
- 异常返回有处理方式；
- 未确认接口必须标记为待确认。

不准出场景：

- AI 编造接口路径；
- AI 编造字段名；
- 字段映射无依据；
- 异常处理缺失；
- 关键接口未确认但写成确定方案。

### 3.5 实现方案可执行

必须满足：

- 页面结构清晰；
- 组件拆分合理；
- 数据流转清晰；
- 状态管理方式明确；
- 接口调用时机明确；
- 错误处理方式明确；
- 方案能直接支撑 Coding。

不准出场景：

- 方案只描述目标，没有实现路径；
- 组件拆分无法落地；
- 数据流不清晰；
- Coding 时仍需要大量反向确认。

### 3.6 交互状态完整

建议覆盖：

- 加载态；
- 空态；
- 异常态；
- 禁用态；
- 权限态；
- 超长文本；
- 弱网 / 超时；
- 重复提交；
- 表单校验。

不准出场景：

- 核心流程缺少关键交互状态；
- 异常场景缺失导致测试无法设计用例；
- 权限态影响功能但未说明。

### 3.7 影响范围明确

必须满足：

- 影响页面明确；
- 影响组件明确；
- 公共组件影响明确；
- 公共逻辑影响明确；
- 回归范围明确；
- 兼容旧逻辑的要求明确。

不准出场景：

- 修改公共组件但未说明影响范围；
- 涉及老页面但未说明回归范围；
- 变更接口或公共逻辑但未说明兼容风险。

### 3.8 风险有闭环

必须满足：

- 风险点明确；
- 影响范围明确；
- 应对方式明确；
- 是否阻断明确；
- 待确认项有责任人和优先级；
- 风险在 `00` 摘要和 `02` 风险清单中保持一致。

不准出场景：

- 只有“存在风险”但没有具体风险；
- 有待确认项但没有确认对象；
- 关键风险没有处理建议；
- P0 待确认项未处理。

### 3.9 依据可追溯

必须满足：

- 需求结论可追溯到 PRD；
- 页面和交互可追溯到设计稿；
- 接口和字段可追溯到接口文档或 Mock；
- 组件复用可追溯到代码上下文；
- 权限和埋点可追溯到规范或人工确认；
- 所有无依据内容都标记为待确认。
- 未读取代码上下文时，代码路径、组件复用、API 封装、类型定义和文件变更建议都标记为待确认。

不准出场景：

- 关键结论没有来源；
- AI 把推断写成事实；
- 复用组件无代码依据；
- 权限、埋点、接口规则无依据。
- 未提供代码来源且未明确不读取代码上下文，却输出确定代码路径、组件复用、API 封装、类型定义或 AI Coding 任务。

### 3.10 模板级别适配

必须满足：

- 产物包已说明使用 L1 / L2 / L3 哪个级别；
- 模板级别与需求复杂度、影响范围和风险匹配；
- L1 方案明确说明接口、权限、路由、埋点、公共组件不涉及；
- L3 方案补充影响矩阵、回归矩阵、灰度 / 回滚和负责人关注点。

不准出场景：

- 应使用 L2 / L3 的需求被降级为 L1；
- 涉及接口、权限或公共组件但省略关键章节；
- 高风险需求没有回归矩阵或回滚方案；
- 省略章节没有依据说明。

### 3.11 AI Coding 上下文可用

必须满足：

- `03_AI_Coding上下文与审核报告.md` 只包含已确认需求、方案、约束和任务；
- 待确认内容被单独列出，不进入“重点实现任务”；
- 禁止项清晰；
- 代码路径、接口、字段、组件复用均有来源。
- 若用户明确不读取代码上下文，AI Coding 上下文不得包含确定代码路径、组件复用、API 封装或类型定义。

不准出场景：

- 未确认接口或字段进入重点实现任务；
- 未授权公共组件修改进入 Coding 指令；
- AI Coding 上下文脱离已确认方案自由发挥。
- 代码来源缺失时仍输出确定 AI Coding 任务。

## 4. 问题等级

| 等级 | 定义 | 处理方式 |
|---|---|---|
| P0 | 阻断问题。影响 Coding、测试或验收 | 必须修复并复审，不允许准出 |
| P1 | 重要问题。可能导致返工或质量风险 | 原则上修复；特殊情况负责人确认后可有条件准出 |
| P2 | 优化建议。不影响流转 | 可后续优化，不阻断准出 |

---

## 5. 准出结论

### 通过

- 无 P0 问题；
- 无未处理的关键 P1 问题；
- 关键结论有依据；
- 产物包结构完整且拆分合理；
- 负责人确认可以进入 Coding。

### 有条件通过

- 无 P0 问题；
- 存在 P1 问题，但不阻断主体 Coding；
- 风险已明确；
- 负责人确认接受风险。

### 不通过

存在以下任一情况：

- 有 P0 阻断问题；
- 关键输入缺失；
- 产物包缺失关键文件且无说明；
- 方案存在明显无依据或编造内容；
- AI Coding 上下文包含未确认实现任务；
- 方案无法支撑 Coding；
- 方案无法支撑测试设计。

## 7. 最关键的原则

> 产物包准出不是看文档是否写得长，而是看不同角色能否各读其所需，并基于它稳定开展 Coding、测试和验收。
