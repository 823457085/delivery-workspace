# 前端技术方案产物包模板

使用场景：需求评审通过后，前端进入技术方案设计阶段。  
目标：生成一组可阅读、可评审、可执行、可审核的前端技术方案产物包，而不是一份超长 Markdown。

设计说明：本模板把原单篇技术方案拆成 4 个文件。拆分边界按读者职责划分：负责人看摘要，研发看实现，测试看验证，AI Coding 看上下文，审核者看风险和准出。模板仍保留 L1 / L2 / L3 分级、防瞎编、证据追溯和 P0 阻断规则；没有拆成更多文件，是为了先落地轻量产物包，避免一次性把 Skill 复杂度拉满。

---

## 使用说明

默认生成 4 个 Markdown 文件：

```text
frontend-tech-solution/
├── 00_前端技术方案评审摘要.md
├── 01_前端实现与接口细节.md
├── 02_测试验收与风险清单.md
└── 03_AI_Coding上下文与审核报告.md
```

主文档 `00_前端技术方案评审摘要.md` 用于评审和决策；其余文件作为执行附件，分别承接实现细节、测试验收、风险清单、AI Coding 上下文和审核报告。

主文档不硬卡字数，但应控制阅读负担：

- 顶部摘要建议 300-500 字；
- 小需求 / 单页面改动正文建议 800-1200 字；
- 中等需求 / 多页面或多组件正文建议 1200-1800 字；
- 复杂需求 / 跨系统协作可放宽到 2500 字左右；
- 详细接口字段、完整测试建议、完整 AI 审核报告必须拆入附件。

L1 / L2 / L3 仍由《09_前端技术方案模板分级规则.md》判定：

- L1：仍输出 4 个文件，但附件可轻量化，并对不涉及章节写明依据。
- L2：使用本模板默认 4 文件结构。
- L3：在 4 文件结构中强化影响矩阵、回归矩阵、灰度 / 回滚、监控告警和负责人准出关注点。

---

## 输出文件格式

生成时必须使用以下分隔格式：

```markdown
--- file: 00_前端技术方案评审摘要.md
<文件内容>

--- file: 01_前端实现与接口细节.md
<文件内容>

--- file: 02_测试验收与风险清单.md
<文件内容>

--- file: 03_AI_Coding上下文与审核报告.md
<文件内容>
```

## 产物一致性要求

1. 四个文件中的需求范围、风险结论、待确认项和准出建议必须保持一致。
2. `00_前端技术方案评审摘要.md` 只写摘要和决策信息，不承载完整细节。
3. `01_前端实现与接口细节.md` 不写无来源的接口、字段、组件、权限或埋点。
4. `02_测试验收与风险清单.md` 必须集中列出风险和待确认项。
5. `03_AI_Coding上下文与审核报告.md` 的 AI Coding 上下文只能包含已确认内容。
6. 只要存在未处理 P0，任何文件都不得写成“建议进入 Coding”或“准出通过”。
