# 前端技术方案产物包输入清单

本文件用于前端技术方案产物包生成前的材料准备。目标是确保 AI 拥有足够、明确、可追溯的上下文，能判断哪些内容可以进入主文档、哪些内容必须进入附件，降低编造接口、字段、组件和实现细节的风险。

---

## 1. 使用时机

在以下阶段使用：

> 需求评审通过后，前端进入技术方案设计前。

完成输入准备后，再执行：

1. 输入完整性检查；
2. 模板级别判定；
3. 技术方案产物包生成；
4. 技术方案产物包审核。

---

## 3. 输入材料总览

| 输入材料 | 是否必需 | 用于哪个产物 | 说明 |
|---|---|---|---|
| PRD / 需求说明 | 必需 | 00、02、03 | 明确需求范围、功能点、验收标准 |
| 设计稿 / 原型 | 必需 | 00、01、02、03 | 明确页面结构、交互、状态 |
| 接口文档 / Mock 数据 | 条件必需 | 01、03 | 涉及接口、字段、数据展示、提交、导出、分页、筛选、排序或状态变更时必须提供 |
| 现有代码上下文 | 必需 | 01、03 | 明确可复用组件、页面、方法、类型、接口封装和限制 |
| 代码来源（localPath / repo / 明确不读取） | 必需 | 01、03 | 指定本地项目目录、远程仓库版本，或明确说明本次不读取代码上下文 |
| 前端代码规范 | 必需 | 01、03 | 约束代码组织、命名、类型、状态管理 |
| 组件库规范 | 强建议 | 01、03 | 避免 AI 编不存在的组件 |
| 路由 / 权限说明 | 视需求而定 | 01、02、03 | 涉及入口、菜单、角色或操作权限时必须提供 |
| 埋点 / 监控规范 | 视需求而定 | 01、02 | 涉及数据统计、链路监控或异常监控时必须提供 |
| 历史类似方案 | 可选 | 00、01 | 提升输出质量和方案深度一致性 |
| 禁止项 / 风险项 | 强建议 | 00、01、02、03 | 明确哪些地方不能乱改，哪些风险需要提前暴露 |

## 4. 输入材料说明

### 4.1 PRD / 需求说明

至少应包含：

- 需求背景；
- 需求目标；
- 需求范围；
- 不做范围；
- 核心功能点；
- 业务规则；
- 边界条件；
- 异常场景；
- 验收标准；
- 依赖方；
- 风险点。

缺失风险：

- 需求边界不清，方案容易扩大或缩小范围；
- 验收标准不清，后续容易反复确认；
- 异常场景缺失，测试阶段容易返工。

### 4.2 设计稿 / 原型

至少应包含：

- 页面结构；
- 主要交互流程；
- 表单项和校验规则；
- 列表字段和展示规则；
- 弹窗、抽屉、Toast、提示文案；
- 加载态、空态、异常态、禁用态、权限态；
- 响应式或适配要求。

缺失风险：

- AI 可能凭经验补交互；
- loading、empty、error、disabled 等状态容易遗漏；
- 页面结构和组件拆分可能不符合设计预期。

### 4.3 接口文档 / Mock 数据

适用规则：

- 涉及接口调用、字段展示、数据提交、导出、状态变更、分页、筛选或排序时，接口文档 / Mock 数据为必需输入；
- 仅涉及纯静态 UI、文案、样式或无数据变更的页面调整时，可不提供接口文档 / Mock 数据，但需要在输入材料中明确说明“不涉及接口和数据变更”。

至少应包含：

- 接口名称；
- 请求方法；
- 请求地址；
- 请求参数；
- 返回字段；
- 字段含义；
- 字段类型；
- 分页规则；
- 排序 / 筛选规则；
- 错误码；
- 异常返回；
- Mock 示例数据。

缺失风险：

- AI 编造接口路径；
- AI 编造字段名；
- 字段类型和展示逻辑不一致；
- 异常处理遗漏；
- 未确认接口或字段错误进入 AI Coding 上下文。

### 4.4 现有代码上下文

代码来源至少提供一种：

- 本地项目：`localPath`
- 远程仓库：`repo`、`ref`，必要时提供 `subdir`
- 明确不读取：说明“本次不读取代码上下文 / 无代码上下文可用”

建议提供：

- 相关页面路径；
- 相关组件路径；
- 相关路由配置；
- 相关状态管理文件；
- 相关接口调用文件；
- 相关工具方法；
- 相关类型定义；
- 相关样式文件；
- 公共组件使用示例；
- 历史类似实现。

缺失风险：

- AI 编造不存在的组件；
- 忽略公共组件影响范围；
- 实现方案脱离现有项目结构；
- 后续 AI Coding 输入不稳定。

### 4.5 规范与限制

建议提供：

- 前端代码规范；
- 组件库规范；
- 权限说明；
- 埋点说明；
- 禁止项；
- 风险项；
- 灰度或开关要求；
- 需要兼容的历史逻辑。

## 7. 输入不足处理规则

1. 缺少 PRD、设计稿、接口文档、代码上下文等关键材料时，不得直接生成完整产物包。
2. 输入不足时，应优先输出待确认问题清单。
3. 如果只能生成部分文件，必须明确说明哪些文件可以生成，哪些文件需要等待补充信息。
4. 未确认的接口、字段、组件、权限、埋点、实现细节，不得进入 AI Coding 上下文包。
5. P0 待确认项处理前，不得建议进入 Coding 或准出。
6. 未提供 `localPath`、`repo/ref/subdir`，且未明确说明不读取代码上下文时，必须先追问代码来源，不得生成包含确定代码路径、组件复用、API 封装、类型定义或 AI Coding 任务的完整产物包。

正确处理方式：

```text
输入不足 → AI 输出缺失信息和待确认问题 → 找对应角色补充确认 → 再生成产物包
```

示例：

| 缺失信息 | 需确认对象 | 影响产物 | 影响 |
|---|---|---|---|
| 导出接口字段未确认 | 后端 | 01、03 | 无法生成字段映射和 AI Coding 任务 |
| 不同角色是否都可导出未确认 | 产品 | 01、02、03 | 无法确定权限逻辑和测试重点 |
| 导出按钮禁用态未说明 | 产品 / 设计 | 02 | 无法确定交互状态 |
| 是否需要导出埋点未说明 | 产品 / 数据 | 01、02 | 无法确定埋点方案 |

---

## 8. AI 输入完整性结论

完成输入检查后，AI 应给出三类结论之一：

| 结论 | 说明 | 下一步 |
|---|---|---|
| 可以生成完整产物包 | 关键信息完整，可以生成匹配模板级别的 4 文件产物包 | 执行技术方案产物包生成 |
| 只能生成部分产物 | 部分信息缺失，但可先生成确定文件或确定章节 | 明确可生成文件、暂不建议生成文件和待确认项；P0 待确认项处理前不得准出 Coding |
| 不建议生成 | 关键输入缺失，生成后瞎编风险较高 | 先补齐输入材料 |

---

## 9. 最关键的规则

> 输入材料决定产物质量。缺少事实输入时，AI 不应补全方案，而应暴露问题。
