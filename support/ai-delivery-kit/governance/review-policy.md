# Review Policy

AI Delivery Kit changes should be reviewed according to blast radius.

## Low Risk

Examples:

- Typo fixes
- Additional examples
- Prompt wording that does not change required outputs

Review:

- One role owner.

## Medium Risk

Examples:

- New prompt
- New optional skill
- New optional template section
- Tool adapter changes

Review:

- Corresponding role owner
- Platform owner when adapters or install behavior change

## High Risk

Examples:

- Gate pass/fail rule change
- Required template field change
- Required artifact change
- Security or compliance rule change

Review:

- Product owner
- Development owner
- QA owner
- Platform owner

High-risk changes should include migration notes.
