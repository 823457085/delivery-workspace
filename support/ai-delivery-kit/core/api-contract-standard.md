# 接口契约规范

> 适用范围：HTTP、gRPC、OpenAPI、内部 RPC、前后端联调接口、Webhook、异步回调和需要在 tech-design / test-plan 中被引用的外部契约。

## 1. 目标

接口契约必须让前端、后端、测试和 AI 工具都能明确：

1. 调用谁、什么时候调用、成功和失败分别是什么。
2. 字段含义、默认值、枚举、兼容性和错误码。
3. 如何鉴权、分页、幂等、限流、审计和回滚。

## 2. 技术方案必填

| 项 | 要求 |
|----|------|
| 接口名称 | MUST 有业务名称和路径/方法 |
| 请求字段 | MUST 标注类型、必填、默认值、约束、示例 |
| 响应字段 | MUST 标注类型、为空场景、分页和状态字段 |
| 错误码 | MUST 区分参数、权限、业务冲突、依赖失败、系统错误 |
| 鉴权 | MUST 说明角色、数据范围、内部调用凭证 |
| 幂等 | 写操作、回调、重试场景 MUST 说明幂等键或幂等策略 |
| 兼容性 | 修改已有接口 MUST 说明向后兼容、灰度和废弃策略 |
| 可观测 | 关键接口 SHOULD 说明日志字段、trace id、指标 |

## 3. 错误码口径

| 类型 | 要求 |
|------|------|
| 参数错误 | 说明哪个字段、什么约束不满足 |
| 权限错误 | 不暴露不该暴露的资源存在性 |
| 业务冲突 | 说明当前状态和允许动作 |
| 依赖错误 | 说明是否可重试、是否降级 |
| 系统错误 | 返回稳定错误码，不泄露内部堆栈和敏感信息 |

## 4. 测试方案要求

测试方案 MUST 为每个关键接口覆盖：

1. 成功路径。
2. 参数缺失、非法枚举、边界值。
3. 权限拒绝和数据隔离。
4. 幂等/重复提交/重试。
5. 依赖失败、超时和空数据。

## 5. Review 判定

| 情况 | 默认级别 |
|------|----------|
| 新增/变更接口但 tech-design 无契约 | blocker |
| 写接口无鉴权或幂等说明 | blocker |
| 错误码缺失导致前端/测试无法判断状态 | major |
| 字段类型、枚举、空值和分页规则不清 | major |
| 缺少示例但不影响实现 | minor |
