# 数据库变更规范

> 适用范围：DDL、DML、migration、索引、数据修复脚本、字段语义变更、表结构废弃、读写路径调整。

## 1. 目标

数据库变更必须保证可评审、可灰度、可回滚或可补偿，避免功能上线后因为数据结构和迁移不可控导致返工。

## 2. 技术方案必填

| 项 | 要求 |
|----|------|
| 表与字段 | MUST 列出新增/修改/废弃表字段、类型、默认值、是否可空 |
| migration | MUST 说明脚本路径、执行顺序、是否可重复执行 |
| 兼容策略 | 线上已有数据和旧版本代码 MUST 可兼容或说明切换窗口 |
| 索引 | 查询条件、排序、唯一约束、写入成本 MUST 评估 |
| 数据修复 | 涉及历史数据时 MUST 提供修复脚本、校验 SQL 和回滚/补偿 |
| 风险 | 大表、锁表、长事务、批量更新、跨库一致性 MUST 标注 |
| 回滚 | DDL 不可逆时 MUST 说明补偿方式和回退窗口 |

## 3. Migration 要求

1. 文件名 SHOULD 包含序号和业务含义。
2. DDL/DML SHOULD 分离；大批量 DML 分批执行。
3. 脚本 SHOULD 幂等或在说明中写清不可重复执行。
4. 不允许在业务高峰直接执行未评估的大表锁表操作。
5. 不允许把生产敏感数据写入测试或文档。

## 4. 测试证据

| 证据 | 要求 |
|------|------|
| 本地/测试库执行 | 记录命令、结果、耗时 |
| 回滚/补偿验证 | 说明验证方式 |
| 关键 SQL | EXPLAIN 或等价说明 |
| 数据校验 | 执行前后 count/checksum/抽样结果 |

## 5. Review 判定

| 情况 | 默认级别 |
|------|----------|
| 有 DB 改动但 tech-design 未说明 | blocker |
| 破坏兼容或数据不可逆且无灰度/补偿 | blocker |
| 大表/批量更新无执行策略 | blocker |
| 索引、唯一约束或查询影响未评估 | major |
| 缺少校验 SQL 或测试执行证据 | major |
