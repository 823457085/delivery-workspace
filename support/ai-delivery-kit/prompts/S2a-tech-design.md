# S2a · 技术方案提示词

| 项 | 内容 |
| --- | --- |
| 阶段 | S2a 技术方案 |
| 输出 | `tech-design.md` |
| 模板 | `artifacts/templates/tech-design.md` |
| Gate | G2a |

## 使用前

提供 PRD、已确认的评审结论、相关代码路径和已知约束。先定位与本期需求相关的实现，再读取模板。涉及接口、数据库、前端状态、单测或可观测性时，按需读取对应专项规范。

## 主提示词

```text
基于 @PRD.md、@review-minutes.md 和相关代码，生成 tech-design.md。使用
@ai-delivery-kit/artifacts/templates/tech-design.md 的结构，中文输出。

先检查本期需求对应的代码、服务、接口和数据模型。不要把未在代码或输入中证实的模块、字段或契约写成事实；对待确认的后端或外部契约明确标为“拟定”。

方案须覆盖本期全部 US/AC，并在覆盖度矩阵中逐项给出证据。影响范围只列实际受影响的服务、模块、接口、数据、配置和任务；不涉及的维度写“无变更”。

根据影响范围补足设计细节：接口契约与错误处理、数据兼容与回滚、前端状态、权限、幂等、可观测性和测试。PRD 差异、风险、人工决策和无法验证的边界应如实说明。

任务拆分应能直接执行并与评审排期一致。输出的是待审核技术方案，不要宣称 G2a 已通过或实现已完成。
```

## 完成检查

- 本期 US/AC 在需求映射和覆盖矩阵中均有对应项。
- 代码路径和现有能力来自实际调研；拟定项已标明。
- 测试、回滚和开放问题与本次变更风险相称。
