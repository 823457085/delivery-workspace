# Sign Hub 自定义插件

独立 `hostApi: 2` 应用包，使用 Sign Hub 的公开 HTTP API；不嵌套远端网页、不读取工作台内部认证文件，也不在宿主注册专属路由。

支持站点及账号管理、密码/Cookie 凭据、验证码、登录校验、手动及批量签到、Cron 计划、执行/通知记录、站点适配器模板与重载、WebDAV 备份和恢复、服务监听设置。站点完整配置、批量导入等复杂结构使用 JSON 编辑器，服务端继续负责校验。返回的业务提示原样展示。

## 安装和配置

1. 在工作台仓库执行 `node plugins/sign-hub/build.mjs`（分发 `package/` 时接收者不需要构建）。
2. 在「功能插件」点击内附 Sign Hub，或检查 `plugins/sign-hub/package` 的绝对目录。
3. 核对来源，显式勾选本机代码信任后安装；按需开启主菜单，图标与排序使用宿主菜单设置。
4. 点击「配置」，填写实际服务地址和自己的管理员令牌。默认地址为 `http://127.0.0.1:8990`；不读取旧 `.local/sign-hub/data/admin.token`。使用远端服务时配置 HTTPS 或自己的可信本机转发地址。
5. 打开插件，刷新列表。修改服务地址时需要重新填写令牌，避免把旧认证发到新地址。

所有服务写入必须先预览再确认。确认令牌绑定当次参数、两分钟有效且仅用一次；失败不自动重放。超时不代表签到、备份或恢复没有执行，应先查询服务端状态。

## 边界与生命周期

- 宿主只提供应用请求桥、配置、安装/启停、主题和剪贴板确认；没有增加 Sign Hub 专属宿主能力。
- 管理令牌只供插件后端使用。账号业务数据仍保存在 Sign Hub 服务端；停用/卸载此插件不停止 Sign Hub，也不取消已经在服务端启用的签到计划、不删除数据。
- 浏览器助手依赖 Sign Hub 官方浏览器扩展和它自己的控制台会话。插件提供复制服务地址的入口，需在独立浏览器中使用助手；不能在隔离插件页直接运行浏览器扩展。普通账号、Cookie 导入及校验可在插件页完成。
- 保留原权限和显式信任要求。worker 不是 OS 安全沙箱，只安装可信代码。

## 来源与验证

接口依据 [ly-wo/sign-hub](https://github.com/ly-wo/sign-hub) 的 `7d8e227`：`src/api.rs`、`src/model.rs`、`src/settings.rs`、`src/backup/remote.rs`。构建和运行不依赖该源码在本机的路径。

`test/service-custom-plugins.test.ts` 覆盖认证、写入确认、不可重放、错误处理、包安装、配置保存、撤权与移除。临时真实 Sign Hub 服务验证了模板读取、站点/账号新增、账号修改与页面回读。未使用真实账号登录网站、签到、发送通知或操作远端备份。
