# Shanlian 自定义插件

独立 `hostApi: 2` 应用，自己的页面通过插件后端访问 Shanlian HTTP API；不嵌套外部控制台。保留连接总览、节点搜索/地区筛选/延迟排序与批量检测、连接/断开/重连、账号登录与刷新、定时刷新、代理监听及网段设置、Clash 订阅/直连链接/规则/全局脚本设置。

## 安装和配置

1. 执行 `node plugins/shanlian/build.mjs`，得到可独立分发的 `package/`。
2. 在工作台「功能插件」点击内附「闪连」，或检查 `plugins/shanlian/package` 的绝对目录。
3. 显式确认信任本机代码并安装；按需开启菜单及调整图标/顺序。
4. 点击「配置」，填写实际服务地址、控制台管理账号和管理密码。服务地址没有预填端口，避免误接其他本机服务。管理账号与闪连服务商账号不同。
5. 打开插件自动建立管理会话；服务商账号仍在插件自己的「闪连账号」页登录。修改地址或管理账号后须重新填写管理密码。

配置的地址必须能被工作台服务端访问；继续遵守 Shanlian 的 Host/Origin、管理网段、登录限流和 CSRF 校验。不修改系统代理，不启动、停止或接管已有 Shanlian 服务。

## 能力与安全边界

- 公开宿主能力：应用请求桥、配置、安装/启停、主题、剪贴板确认；无新增宿主业务分支。
- 管理 Cookie、CSRF 和配置密码只留在插件后端，页面只得到认证结果与业务数据。
- 选节点、连接变更、账号登录/刷新、保存网络/计划/订阅等写入均先预览确认。预览绑定参数且单次有效，失败不自动重试；延迟和网络检测只由用户点击触发。
- “退出控制台”清除本插件进程中的管理会话，不断开服务器代理；重新连接会按已保存的插件配置登录。
- 停用/移除会终止插件自己的进程与未完成请求；远端代理、订阅和已经启用的定时刷新由 Shanlian 服务继续管理。卸载不删除远端数据，也不撤销已发出的远端操作。
- 原生表单提交被应用容器禁止，页面使用受控请求桥；不放宽容器权限。

## 来源与验证

页面与契约适配自 [ly-wo/shanlian-rs](https://github.com/ly-wo/shanlian-rs) `85dcc0d` 的 `web/` 与 `src/web.rs`。页面资源已包含在插件源目录，构建无需外部源码目录；Node 后端不启动 Rust 二进制。

`test/service-custom-plugins.test.ts` 验证管理会话、CSRF、固定接口、写入确认、不重放、安装/配置/启停。浏览器使用模拟服务验证节点筛选、选中回读与定时设置保存。未连接真实服务商账号、未切换用户的真实代理网络。
