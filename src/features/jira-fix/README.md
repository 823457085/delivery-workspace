# Jira 修复

入口为 `/agent?view=jira-fix`，在「执行」中与「需求开发」并列。

## 新建修复（同步 Jira 研发助手 1.2.1）

表单来自插件：读取测试缺陷，选择“新建开发 Jira”或“使用当前 Jira 直接修复”，从本机扫描结果选择项目、基准分支与工作分支，生成任务预览。新建开发 Jira 时，确认后才创建前端任务并关联原缺陷，回读后再开始；结果不明只读核对，不重复建单。

开始时工作台从 `origin/<基准>` 拉取最新提交，在项目同级 `*-tasks/` 下创建独立 worktree，然后用底部所选 **CLI（Codex / Claude Code / Cursor）、模型、推理强度和访问权限** 在工作台启动会话并打开，不新建 Codex 聊天。会话登记为下方修复记录，交接、验收照旧。实现见 `src/features/jira-dev/` 与 `server/jira-dev/README.md`。

以下为原有记录、交接与重试说明（旧版“克隆仓库”表单已由上面的流程替代，历史记录保留）。

- 读取已配置 Jira 的事项；自动匹配已保存的 Jira 项目配置，以及任务/父任务对应的本地分支和目录。多个仓库保留选择，不静默选第一个；无法匹配时可选择本地项目或手工输入仓库。
- 配置仓库、保存父目录、远端基准分支和 `feature/` 修复分支。勾选记住配置后，后续同 Jira 项目可自动回填；配置保存在 `.data/jira-fix/projects.json`。
- 启动时重新读取 Jira，在父目录下创建唯一目录、克隆代码、从基准分支的远端 SHA 创建分支，再启动工作区权限的修复会话。不会切换原检出的分支或覆盖未提交文件。
- 修复授权仅含 Jira 读取、代码修复和验证。提交、推送、MR、部署及 Jira/Confluence 写入不在默认授权内。
- 启动记录与 Agent 通过稳定 sourceId 关联。重复请求复用结果；服务中断不会自动重放；克隆失败保留目录供核对，不自动清理用户目录。会话结束不等于问题验收。
- 启动失败且未创建会话的记录可点击「重试」，沿用原配置创建新尝试，保留历史记录和失败目录；准备期间禁止重复点击。Git 错误保留失败步骤和原始原因，不将连接超时统一描述成权限问题。
- 用户生成的交接评论草稿自动保存在本机，再次打开同一轮可恢复；人工编辑另保存在当前浏览器。新运行或来源结果变化时不套用旧稿，生成失败保留已有内容。自动保存不启动额外模型调用，不发布评论、流转 Jira 或确认验收。
- 新修复会话的最终答复会要求提供四段 `delivery-report`。运行成功结束并完成落盘后，工作台自动保存合规报告为待确认交接稿，打开交接即可预览；同轮已有草稿保留，人工编辑优先。历史运行不自动补生成，缺少或无效报告仍可使用原“生成评论”入口。
- 同一报告的 `validationEvidence` 会在当前轮完成并落盘后用于验收表单预填；同来源人工证据优先，旧轮证据不复用，不自动保存或验收通过。验证字段无效只跳过证据预填，不影响合法交接稿导入。

验证：`tsx --test test/jira-fix.test.ts test/jira-fix-retry.test.ts test/requirement-development.test.ts test/agent-workspace-navigation.test.ts`。测试使用临时 Git 仓库和受控 Agent，不修改真实 Jira。
