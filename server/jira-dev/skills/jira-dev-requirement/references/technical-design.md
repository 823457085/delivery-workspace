# 前端技术方案内容指引

在实际读取需求和代码后使用。方案篇幅与改动规模相称，不为小需求附加架构重构；下列内容可合并表达，但结论必须有来源。

## 需求与验收映射

- 产品需求、已登记的前端父任务与实现任务，或明确本地待登记状态。
- 需求/验收点与对应前端行为、验证方式；差异和待确认问题只影响具体依赖动作。
- 目标版本按已提供事实记录，未指定时明确未指定。

## 实际代码现状

- 已读文件与关键入口、调用、状态、请求和已有复用点。
- 工作区、分支、基准 SHA；说明现有行为如何覆盖或缺失需求。
- 不用计划中的文件冒充已经存在的代码，不收集敏感配置。

## 改动与状态

- 本次页面、交互、数据流和关键状态如何变化；保留范围外现状。
- 入口、加载、成功、空态、失败、返回与重试等受影响路径，沿用项目已有反馈，不自行新增提示面板。
- 权限或业务判断使用明确来源，无法确定的依赖单列。
- 记录本任务“使用多语言位置编码：开启/关闭”的显式选择。开启或未提供开关且按旧任务默认适用时，说明实际目标端、语言初始化与语言包、受影响静态文案、既有位置码前缀及必要校验和导入表计划；显式关闭时不安排新增位置码或强制导表，保留已有 i18n 运行、调用和 key。只依据所选项目与本次任务要求，不引用其他仓库的开发约定。

## 接口与暂拟契约

- 已确认接口和字段标注证据来源。
- 后端尚未确认的字段、映射和时区集中说明为暂拟，放在适配层；写明对齐位置与 mock 验证范围。
- 展示字段返回什么就显示什么；不要翻译或改写接口文案。

## 验证与回滚

- 各验收点对应的必要测试/页面路径，预期结果与真实接口待验证项。
- 受影响调用和回归边界；实际执行后在交接中记录结果，方案中的计划不宣称已经通过。
- 说明如何撤回本次改动或关闭已存在的开关；没有开关时不为回滚凭空新增开关。

## 保存与继续执行

先将完整正文和实际已读代码证据交给 `complete_jira_dev_technical_design`，核对已保存的 Markdown 文件；已有方案核验后附来源。没有面板 `taskId` 时自行保存实际本地文件，不伪造标识。

只有面板计划同时包含已确认的 `designDestination` 和 `designPublicationAuthorized: true`，或直接使用技能时用户另有明确发布授权，才按 [Confluence 方案发布指引](confluence-publication.md) 将本任务方案放到指定父页下；不能从计划状态或恢复记录推定授权。先保存本地，再发布并回读已保存文件的完整正文和归档位置；成功后登记包含正文 SHA-256 的 `publication` 证据，优先使用保存工具返回的 `sha256`。已有方案在其他位置时仅作来源，不移动或覆盖原页面。

交接分别记录本地路径与 Confluence 页面 URL、版本、直属父页；保存本地文件不等于已发布，发布成功也不等于开发完成。发布受阻时保留本地文件和待发布/待核对状态，继续独立的实现和验证。
