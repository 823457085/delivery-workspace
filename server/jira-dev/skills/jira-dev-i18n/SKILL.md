# 海外项目多语言

先读取本次 `useI18n` 和任务指令“使用多语言位置编码：开启/关闭”。本次显式选择优先于插件或其他技能的默认启用规则。

- 开启时，按目标项目实际机制执行以下流程，仅处理本次改动，不顺带改造历史文案；没有新增或修改前端文案时，核验后记录“不涉及文案变更”。
- 关闭时，停止本专用流程，不新分配位置码、不强制生成导入表，不因海外项目或其他技能默认要求而重新开启。新增普通文案遵循本次任务要求，保留已有 i18n 运行、原有调用和存量 key，不移除或替换它们；接口展示文案始终原样显示，包括 `L` 码。
- 未提供开关的旧任务沿用既有默认：海外 Apex、PC、App 需求适用；修复按实际改动范围和项目规则判断；其他项目按其自身规则和需求判断。以下步骤只对开启或旧任务默认适用的情况执行，缺省不视为显式选择。

## 先确认目标项目

- 以任务选定的来源项目和本任务独立工作区为准，读取它们适用的项目规则、`package.json`、语言初始化文件和相邻业务代码。不要继承面板聊天所在的其他仓库规则，不按 Jira Key、文件夹名字或当前默认 cwd 猜终端。
- 核实 `TERMINALNAME`、现有 `t()` / `$t()` 用法、语言包合并顺序、远端覆盖与缓存机制；记录本次使用的端、语言文件和页面前缀。Apex、PC、App 分别使用 `APEX`、`PC`、`APP`，仍须与目标代码核对。
- [三端适配与命令](references/project-i18n.md) 说明三端常见文件差异和随包工具。这些是查找线索；执行时以目标项目实际文件为准。不能把另一个项目的架构、UI 文案或国际化开关规定带进来。
- 本流程不修改语言加载架构、不新增国际化依赖，也不启用其他项目的国际化机制。缺少目标配置或项目身份有冲突时先查实际代码，不能静默使用 Apex 默认值或在未核对前宣称已完成。

## 在实现中完成文案接入

1. 列出本次新增或修改的前端静态文案，包含按钮、标题、校验、提示、占位符、表格和导出表头。接口返回的展示文案、业务数据及用户输入不在提取范围；核对字段后原样显示，包括 `L` 码。接口有 `message` 时沿用接口原文，仅前端已有兜底或自有静态文案走国际化。
2. 优先沿用当前页面已有位置码及调用方式。原位置文案修改时更新对应词条，不因修改文案重建位置码；需要新增位置时按目标项目既有业务前缀创建独立编码。数字递增格式采用 `<终端><页面前缀><四位序号>`：先搜索相同前缀的已有编号，再从最大值后递增，保持大写。页面前缀不固定四位，例如 `APPPAR0001` 的前缀是 `PAR`。
3. 保留存量哈希码，不为统一格式重编号。不因中文相同就复用其他 UI 位置的编码；明确共用的现有组件/业务位置继续沿用原码。旧扫描脚本的生成规则与当前页面不一致时，不直接运行其全量替换。
4. 复用已有英文与项目术语；缺失时按已确认业务含义生成英文草稿并标明待核对，不把草稿写成已获产品确认。其他语种有可靠来源才填写。App/PC 没有本地中文包时，将本次中文原文放在任务临时映射中，英文接入实际基础包；不要凭空给应用添加 `zh-CN.json` 或改动加载链路。
5. 插值保持完整句子，逐项核对调用参数；HTML 留在模板内，不能把标签和属性当翻译原文。核查 `@`、`{}`、`|` 等 Vue I18n 消息语法，普通字符用目标版本支持的字面量或参数表达。

## 验证与导入表

- 以本次相关的已跟踪 diff 和未跟踪业务文件为范围复查遗漏硬编码、缺少位置码、编号冲突、参数和默认语言显示。已有扫描器先读实现，确认支持限定范围；没有可用扫描器时，用定向搜索结合实际代码逐项检查，不扩为全仓替换。
- 使用目标项目版本的 Vue I18n 验证本次新增或修改的 key/消息。优先复用项目已有的增量检查；否则运行随包 `scripts/validate_vue_i18n_messages.mjs`，传入真实项目路径、语言文件和明确 key 清单。缺少依赖、key 不存在或校验失败不能记为通过。
- 有需导入平台的新增或修改词条时，按 [导入表规则](references/project-i18n.md) 使用随包脚本和空白模板生成只含本次词条的 Excel，保存为 `tempdocs/<当前绑定任务编号>-多语言.xlsx`（例如 `OPAY-797-多语言.xlsx`），统一使用 15 列中文表头。英文同时写入“原文”和“英语”，中文写“中文”，无来源的其他语种留空。已有英文优先；英文未能确定时单列待补，不把缺失的表格宣称为已完成交付。
- 读取产物核对表头、端、页面 ID、key、行数和文本。表格与 key 清单默认保留本地；遵守目标仓库对语言源文件的实际跟踪规则，不把个人机器的 `zh-CN.json` 提交习惯强加给所有项目。
- 运行本次必要的项目检查及可用页面路径。构建可能先下载并覆盖语言包，执行前读脚本并保护本次修改；静态消息校验通过不等于远端语言包已生效。

交接记录目标端、改动语言文件、key 范围、导入表路径、实际校验命令和结果、页面验证与待翻译/待平台导入项。生成导入表不等于上传或发布；插件不会因此自动登录多语言平台、提交代码或推送。
